# Wikilinks — типизированный кросс-линк проход

Отдельная **финализирующая стадия** после ingest. Связи проставляются **одним проходом по всему набору страниц**, когда они уже созданы, — а не по ходу письма. Это самая ценная часть графа: распиленная без связей книга = та же книга в кусках.

## Почему отдельным проходом

Пока пишешь страницу, ты не знаешь всех соседей. После ingest набор страниц полон → можно проставить связи корректно и двунаправленно за один проход.

## Шаги

1. **Реестр страниц.** Собрать список всех `wiki/*.md`: путь, `title`, `aliases`, `type`. Это whitelist допустимых целей ссылок.
2. **Связывать по смыслу, не по буквальному совпадению имён.** По каждой странице пройти реестр (title + aliases + лиды/«На этой странице») и найти **семантически связанные** концепты — отношение часто не названо теми же словами. Это LLM-проход по компактному реестру (на нашем масштабе он влезает в контекст), **не** BM25/эмбеддинги. Найденное → в блок **«Куда идти дальше»** типизированной ссылкой. Буквальное совпадение title/aliases — лишь подсказка, не граница.
3. **Только на существующие страницы.** Не выдумывать цели. Если концепт упомянут, но страницы нет — это сигнал «создать страницу» (передать в lint как пробел), а не битая ссылка.
4. **Тип связи** — по смыслу (можно свободным текстом):
   - «X строится на / обобщает Y» → Y предпосылка / X частный случай;
   - «X идёт после Y» → следующий шаг;
   - «X противоречит / отличается от Y» → противопоставление;
   - лист принадлежит теме → родитель-хаб.
5. **Двунаправленность.** Если A ссылается на B — проверить, нужна ли обратная ссылка B→A (часто да, но с другим типом: A «частный случай» B ↔ B «родитель-хаб»/«общий приём» для A).
6. **Inline-глоссы.** При первом упоминании внешнего концепта на странице — короткая расшифровка в тексте (см. `schema.md` инвариант 7), чтобы лист читался самодостаточно.
7. **Формат ссылки.** Только обычная markdown-ссылка: `- [Имя](имя.md) — <тип/как связано>`. Без Obsidian `[[ ]]`/dual-link — выход agent-agnostic.

## Инвариант связности

После прохода — проверить: **каждая страница достижима из `index.md` через хабы** (одну или несколько ссылок).

- **`index.md` = карта хабов** (точек входа); до неск. сотен страниц — с вложенным списком листьев под каждым хабом (полное оглавление, см. `schema.md`).
- Каждый **хаб** перечисляет свои листья (сгруппированные), даёт «С чего начать».
- **Сироты** (недостижимы из index) → привязать к подходящему хабу, либо вынести в lint-отчёт. Не оставлять висящими.

## Безопасность правок

- Один файл за раз; править через точечные правки, не переписывать страницу целиком.
- Не вставлять ссылки внутрь блоков кода и вербатим-цитат.
- Не трогать `sources/`.

## Когда закончил

Посчитать связи; страницы с 0 входящих/исходящих — пометить как кандидатов на привязку (вход в lint). Обновить `index.md`/хабы. Запись в `log.md` — date-заголовок `## YYYY-MM-DD` + строкой ниже `wikilinks | связей N, сирот K`.
