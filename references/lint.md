# Lint — целостность графа (health + lint)

Проверка здоровья вики. Два уровня. **Только отчёт + предложения** — правки применять лишь с одобрения пользователя; деструктивное никогда не молча.

## Запускать независимым сабагентом

Lint исполнять в **изолированном контексте** (Task): агент, который только что писал страницы, привязан к ним и смягчает критику. Свежий контекст судит жёстче.

## health — дёшево, каждую сессию (без тяжёлого LLM)

Быстрая проверка перед работой («не линтить пустой файл»):
- пустые / заглушечные страницы (< ~100 символов тела);
- рассинхрон `index.md` ↔ файлы на диске;
- покрытие `log.md` ↔ `sources/` (все источники зафиксированы);
- битые markdown-ссылки: **резолвить путь относительно расположения файла, а не по совпадению basename** — ссылка из `index.md` (корень) на страницу в `wiki/` должна вести в `wiki/<файл>`, иначе она битая (частая ловушка: писатель линкует страницы голым именем из корня).
- вербатим-якоря: текст якоря дословно на указанных строках источника (`grep` + нормализация) → не сошлось = предупреждение «проверь строки» (страхует номера строк, не смысл). **Минимум нормализации перед сравнением, без него до 5–10 % якорей валятся ложно:** юникод-кавычки/тире/nbsp → ASCII-эквиваленты; markdown-эмфазис снять **полностью** — не только парный `*…*`, но и `**жирный**` и непарные `*` (одиночный regex `\*([^*]+)\*` не берёт `**…**` и оставляет стрелочные `*`); надёжнее просто удалить все `*` из нормализованного текста (в прозе они не значимы), иначе цитаты из EPUB с `**Заголовок.**`/`*курсив*` валятся ложно; эллипсис в цитате (`…` U+2026 и ASCII `...`) трактовать как **маркер пропуска** — split цитаты на чанки и искать каждый в источнике **по порядку**, а не одной подстрокой. **Нормализовать ВСЕ варианты кавычек, включая `„` (U+201E низкая открывающая) и `‟`** — иначе цитаты с немецким/русским типографским оформлением (`„…"`) валятся ложно. **И не обрезай захваченную цитату для матчинга** (обрезка `quote[:60]` — только для дисплея в отчёте): по обрезку диапазон строк подбирается ложно-коротким, и якорь «проходит» проверку, фактически не покрывая конец цитаты.
- `.manifest.json` ↔ диск: у всех источников из `sources/` есть `content_hash`; затронутые страницы существуют; manifest не расходится с `log.md`. Рассинхрон → предупреждение (enrich может задублировать).

## lint — периодически (раз в N ингестов), глубже

1. **Инвариант связности.** Каждая страница достижима из `index.md` через хабы. Сирота → **предложить** привязку к хабу или удаление; применять — отдельным подтверждённым fix-проходом, не в lint.
2. **Битые ссылки** между страницами (резолвить путь относительно файла, не по basename — см. health).
3. **Дубли** (один концепт на двух страницах) → предложить слияние (canonical по: больше входящих ссылок → длиннее → больше источников).
4. **Соответствие контракту + conformance OKF v0.1** (`schema.md`):
   - **Концепт-доки `wiki/*.md` (включая хабы)** — парсимый frontmatter и **непустой `type`** (нет `type` = fail; это жёсткое требование OKF). Поле `category` в новых страницах — **fail** (legacy, должно быть `type`).
   - **Reserved-файлы.** `index.md` — **без frontmatter**, кроме допустимого `okf_version: "0.1"` в корневом (любой другой YAML в `index.md` = conformance-fail). `log.md` — date-заголовки строго `## YYYY-MM-DD` (скобки `## [..]` = fail).
   - **Листья** дополнительно — лид, «На этой странице», **≥1 вербатим-якорь с диапазоном строк**, типизированные связи, блок «Источники». **Хабы** — карта темы, «С чего начать»; с них **не** требовать `sources`, вербатим-якорь и «Источники», иначе ложные срабатывания. `type: redirect` — легитимная заглушка, не пустышка/сирота.
5. **Размер страницы.** Перерос ориентир (~800 слов) → предложить **split** (несколько концептов) или **shorten** (один, но многословно).
6. **Phantom hubs / пробелы.** Концепт упомянут на ≥2 страницах, но своей страницы нет → приоритетный кандидат «создать страницу».
7. **Data-gap подсказки.** «По теме X в вики нет источника — рассмотри добавить Y» (предложение к enrich, не выдумка фактов).
8. **Провенанс.** Утверждения, поданные как слова автора, но без якоря → пометить; синтез без опоры → пометить.
9. **Противоречия.** Найденные расхождения источников представлены явно (не сглажены) — см. `schema.md`.

## Метрика масштаба (когда индекс/хаб пора дробить)

Связывающее ограничение — **размер навигационного узла** (`index.md` и каждый хаб), не число источников.
- Каждый узел держать **≤ ~неск. сотен строк / ~2–6k токенов**, маршрут до листа ≤ 1–2 переходов.
- Через хабы вики спокойно держит **~1000–2000 страниц без эмбеддингов**. Плоский единый индекс без хабов — потолок ~100–300 страниц.
- Хаб раздулся → lint предлагает **разбить на под-хабы** (второй уровень). Только когда даже хаб-маршрутизация ненадёжна (хабов слишком много / не попасть в нужный) → BM25, дальше эмбеддинги (отложенное расширение, не ядро). `[пороги — эвристика, уточнять на практике]`
- **Плотность `index.md`:** пока он влезает в норму узла (≤ ~неск. сотен строк) — держать **полное иерархическое оглавление** (хаб → все его листья вложенно), это даёт «вид всей структуры с одной страницы». Перерос норму → схлопнуть до карты хабов (листья — только в хаб-страницах). Lint: если индекс — лишь перечень хабов, а вика мала (≤ неск. сотен страниц) → предложить развернуть до полного оглавления.

## Вывод lint

Отчёт человеческим языком (не коды проверок): что нашли, что предлагаем. Список правок → **применять только с одобрения**. Запись в `log.md` — date-заголовок `## YYYY-MM-DD` + строкой ниже `lint | N проверок, сирот K, дублей M, предложено P правок`.
